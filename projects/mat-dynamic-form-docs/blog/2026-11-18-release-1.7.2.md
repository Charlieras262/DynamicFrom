Mat Dynamic Form 1.7.2 is about the apps around the form: it now works with moment and other date adapters,
with several forms on one page, inside a Shadow DOM, with server-side rendering, with any Bootstrap version and
in day-first locales.

<!-- truncate -->

## Moment and other date adapters

Apps that configure `MomentDateAdapter` got errors such as `this.today.setHours is not a function` or
`date.toDateString is not a function` when opening a date-time picker. The calendar now compares dates through
the `DateAdapter`, and the pickers accept `Date`, moment, Luxon or Day.js values and limits.

The library also stopped registering `MatNativeDateModule` for the whole app, which could replace your adapter
depending on the import order. If your app has other Material datepickers and no date adapter, import
`MatNativeDateModule` yourself.

## Several forms, Shadow DOM and SSR

Element lookups used `document.getElementById`, so with two forms using the same node ids the second form's
events, focus or file inputs acted on the first one. Lookups now stay inside each form, which also makes the form
work inside a Shadow DOM and on the server. Use the new `structure.getNodeElement(id)` when you need a node's
element.

## Locales and layout

- Typed dates are read with the node's `dateFormat`: with `dd/MM/yyyy`, `06/05/2025` is 6 May.
- `InputNumber` accepts `1,5` as `1.5`.
- The form has its own scoped layout styles, so it looks right with Bootstrap 4, Bootstrap 5 or no Bootstrap.
- Texts of the file upload and date range are configurable.

## Angular 16

The package is built in View Engine format, which Angular 16 cannot load. The peer dependencies now say Angular
11 to 15, so npm warns before installing it on Angular 16.

The [App compatibility](/docs/guides/app-compatibility) guide lists every setup that is tested, and the
[changelog](/docs/changelog#172) has the details.

## Get it

```bash
npm install mat-dynamic-form@1.7.2
```
