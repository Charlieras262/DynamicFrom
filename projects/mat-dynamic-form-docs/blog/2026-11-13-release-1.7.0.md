Mat Dynamic Form 1.7.0 stops shipping app-level Angular modules, so the library works in lazy-loaded modules
and every app chooses its own animations. It also comes with a spec suite that covers every component, and the
fixes those specs uncovered.

<!-- truncate -->

## Your app picks the animations

Up to 1.6.x the library imported `BrowserAnimationsModule`. Because that module brings `BrowserModule` with it,
importing `MatDynamicFormModule` in a lazy-loaded module failed with `BrowserModule has already been loaded`,
and an app could not rely on `NoopAnimationsModule` because the library's providers might win.

From 1.7.0 your root module imports the animations module it wants:

```ts
@NgModule({
  imports: [BrowserModule, BrowserAnimationsModule, MatDynamicFormModule],
})
export class AppModule {}
```

Most apps already have this line from `ng add @angular/material`. If yours does not, add it. The
[upgrade guide](/docs/migration/upgrade-to-1.7.0) has the details.

## 165 specs, and the bugs they found

Every component, model, utility and pipe now has specs, and the release is published only when they pass.
Writing them uncovered bugs that are fixed in this version, among them:

- The date-time picker lost the chosen time when you changed the day.
- The file upload lost its error state, so the retry and remove buttons never showed up.
- `AutoComplete` made two HTTP requests for its options.
- Some positional constructor arguments ended in the wrong property.

The [changelog](/docs/changelog#170) lists all of them.

## Get it

```bash
npm install mat-dynamic-form@1.7.0
```
