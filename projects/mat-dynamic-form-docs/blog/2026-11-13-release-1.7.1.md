Mat Dynamic Form 1.7.1 makes `apply` work like Kotlin's `apply { }`: besides an object, it now accepts a block
that receives the node, so configuration that needs logic stays inline.

<!-- truncate -->

## `apply` with a block

Until now `apply` only took an object with the properties to assign. That is great for plain values, but not
for anything computed or conditional. Now you can pass a function:

```ts
new DatePicker('checkOut', 'Check-out').apply(picker => {
  picker.minDate = new Date();
  picker.maxDate = new Date(picker.minDate.getFullYear(), picker.minDate.getMonth() + 1, picker.minDate.getDate());
  if (this.isEditing) picker.readOnly = true;
});
```

The parameter has the exact type of the node, so typos and wrong types are compile errors. With a `function`
expression the node is also `this`, like the receiver of Kotlin's lambda. `apply` still returns the same
instance, and the object form keeps working, so both can be chained.

## Reusable blocks

The new `ApplyBlock<T>` type lets you write a configuration once and use it on many nodes:

```ts
import { ApplyBlock, Input } from 'mat-dynamic-form';

const required: ApplyBlock<Input> = input => {
  input.validator = Validators.required;
  input.errorMessage = 'This field is required';
};

new Input('name', 'Name').apply(required);
new Input('email', 'Email').apply(required).apply({ icon: 'email' });
```

## Peer dependencies

`@angular/forms`, `@angular/platform-browser` and `rxjs` are now declared as peer dependencies. Every Angular app
already has them; now npm checks their versions.

The [changelog](/docs/changelog#171) has the details, and the [apply guide](/docs/getting-started/first-form#the-apply-method)
shows every form.
